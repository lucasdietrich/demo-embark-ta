# myta

OP-TEE project generated by Embark:

| Directory | Content |
| --- | --- |
| `ta/` | Trusted Application (secure world), UUID `c081257b-243b-581e-8cc2-a3895ee16564` |
| `include/`, `src/` | Normal-world client library `libmyta.so` (libteec) |
| `examples/` | Demo application `myta-demo` using the client library |
| `rust/` | Rust wrapper of the client library: raw FFI (`src/ffi.rs`), safe `Session` API (`src/lib.rs`) and `examples/demo.rs` |

## Prerequisites

- Cross toolchain: `source .env`.
- OP-TEE TA dev kit (`export-ta_<arch>` of the OP-TEE OS build running on the
  target), `ta/` is built with its `mk/ta_dev_kit.mk`. Set
  `TA_DEV_KIT_DIR` to its path in `.env` (default: the one of the Yocto SDK).
- python3 with the `cryptography` module in `PATH` to sign the TA.
- The TA is signed with `keys/default_ta.pem` of the TA dev kit unless
  `TA_SIGN_KEY` is set: it must match the key of the OP-TEE OS of the target.

The project is personalized in `.env` (`TA_DEV_KIT_DIR`, `TA_SIGN_KEY`).

## Workflow

```sh
source .env
just build           # normal-world side (meson) and TA (`just ta`)
just ta              # TA only, signed c081257b-243b-581e-8cc2-a3895ee16564.ta in build/ta
just deploy          # copy the binaries to mpx:~ and the TA to /lib/optee_armtz
just run-target      # start tee-supplicant if needed, run the demo application on the target
just rust-run-target # deploy, then run the Rust example of the wrapper on the target
```

## UUID

The UUID names the signed TA and is used by the clients to open a session. It
is defined twice and both must agree:

- `BINARY` in `ta/Makefile`
- `TA_MYTA_UUID` in `ta/include/myta_ta.h`
